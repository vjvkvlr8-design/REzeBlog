# GitHub Copilot Instructions for 하데스 System

## 핵심 규칙
- 모든 작업 요청을 처리하기 전에 `정체성.txt` 파일을 먼저 읽고, 그 내용을 우선적인 설계 문서로 인식합니다.
- 이 파일의 내용이 프로젝트의 현재 구현 방식과 내부 동작을 설명하므로, 새로운 기능을 추가하거나 수정할 때는 반드시 이 문서의 규칙을 따릅니다.
- `정체성.txt`에 명시된 프로젝트 정체성, 작업 방식, 품질 기준 등을 우선합니다.

## 작업 수행 방식
- 새로운 기능을 구현하거나 기존 코드를 수정할 때는 다음 순서를 따릅니다:
  1. `정체성.txt`를 읽고 현재 프로젝트 정체성과 의도된 구조를 확인
  2. 사용자 요청을 정체성과 비교하여 호환 여부 판단
  3. 요청이 정체성과 충돌하면 우선 정체성 내용을 유지하며, 필요한 변경 사항을 명확히 설명
  4. 변경 작업을 진행하면서 정체성과 코드 흐름이 일치하도록 구현

## 추가 안내
- 프로젝트의 다른 문서나 코드도 참고하되, `정체성.txt`는 이 프로젝트에서 가장 중요한 교정 문서로 취급합니다.
- 새 작업은 가능하면 `precommit_gate.py` 또는 `cli_gate.py`를 통해 시작해야 합니다.
- `훅스/pre-commit`과 `설정/.pre-commit-config.yaml`이 자동 교정 경로를 제공합니다. 이 설정은 에이전트가 빠르게 스스로 수정하고, 실패 시 상세하게 경고하도록 설계되었습니다.
- 이 지침은 새로운 Copilot 세션이나 에이전트가 하데스 시스템을 사용하는 워크스페이스에서 작업할 때 우선 순위를 높이도록 설계되었습니다.
