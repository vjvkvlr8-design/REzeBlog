# 스토리 기반 게임 제작

**플레이어를 사로잡는 서사 설계의 비밀**

## 스토리 게임이란?

**스토리 기반 게임(Story-based Game)**은 게임플레이보다 **내러티브(Narrative)**가 중심이 되는 장르입니다. Life is Strange, Detroit: Become Human, Firewatch 같은 게임들이 대표적입니다.

### 장르 스펙트럼

```
[완전 게임플레이] ←————————————→ [완전 스토리]

Doom        Portal        Zelda       Uncharted      Life is Strange     Visual Novel
(액션)       (퍼즐)       (어드벤처)   (액션어드벤처)   (스토리 중심)       (텍스트 중심)
```

### 왜 스토리 게임인가?

1. **감정적 연결**: 플레이어가 캐릭터와 정서적 유대감 형성
2. **재플레이 가치**: 다른 선택으로 다른 경험
3. **스트리밍 친화**: 시청자 몰입도 높음 (Twitch/YouTube)
4. **개발 효율성**: 그래픽보다 콘텐츠에 집중 가능

## 서사 설계의 3요소

### 1. 캐릭터 설계

**잊지 못할 캐릭터 만드는 법:**

| 요소 | 설명 | 예시 |
|------|------|------|
| **목표(Goal)** | 캐릭터가 원하는 것 | 엘리: 조엘 구하기 |
| **동기(Motivation)** | 왜 원하는가 | 과거 상실의 트라우마 |
| **갈등(Conflict)** | 장애물 | 좀비 아포칼립스 |
| **성장(Arc)** | 변화 | 자기 중심 → 희생 |

**캐릭터 프로필 템플릿:**

```markdown
## 캐릭터 프로필: [이름]

**기본 정보**
- 나이: 
- 직업: 
- 성격 키워드: 

**내면적 특성**
- 가장 큰 두려움: 
- 가장 큰 소망: 
- 트라우마/상처: 

**외적 특성**
- 외모 특징: 
- 말투/버릇: 
- 특이사항: 

**스토리에서의 역할**
- 목표: 
- 동기: 
- 성장 곡선: 
```

### 2. 플롯 구조

**3막 구조 (서사학의 고전):**

```
[1막: 설정] 25%
├── 훅 (Hook): 플레이어의 관심 끌기
├── 세계관 소개
├── 주인공 소개
└├── 사건 (Inciting Incident): 변화의 시작
    
[2막: 전개] 50%
├── 하위 목표 설정
├── 장애물 등장
├── 도전과 실패
├── 중간 결정점 (Midpoint): 변화의 계기
└├── 더 큰 위기
    
[3막: 결말] 25%
├── 클라이맥스: 최대 위기
├── 결정적 선택
└── 해결/엔딩
```

**게임 특화: 분기형 3막 구조**

```
[1막: 도입] → 플레이어 선택 1 (A/B/C)
                    ↓
[2막: 전개] → 결과에 따른 다른 경로
                    ↓
[3막: 결말] → 3-5개 다른 엔딩
```

### 3. 세계관 빌딩

**설득력 있는 세계 만드는 법:**

**레이어 1: 물리적 세계**
- 지리, 기후, 시간대
- 기술 수준, 마법 시스템
- 사회 구조, 정치 체제

**레이어 2: 문화적 세계**
- 종교, 신화, 전설
- 언어, 방언, 속어
- 예술, 음악, 문학
- 음식, 의복, 건축

**레이어 3: 개인적 세계**
- 개인의 가족사
- 직업, 취미, 일상
- 대인관계 네트워크

## 몰입도 극대화 기법

### 1. 쇼, 돈 텔 (Show, Don't Tell)

**나쁜 예:**
> "그는 슬펐다."

**좋은 예:**
> "그는 창밖을 바라보며 커피를 마셨다. 커피가 식어도 한 모금 더 마셨다. 창문에 비친 그의 얼굴은 눈물 자국이었다."

**게임에서 적용:**
- ❌ 텍스트: "당신은 두려움을 느낀다"
- ✅ 쇼: 심장 소리, 떨리는 손, 어두워지는 시야

### 2. 선택의 무게

**의미 있는 선택 설계:**

| 특징 | 좋은 예 | 나쁜 예 |
|------|--------|--------|
| **결과** | 장기적 영향 | 즉시 끝남 |
| **도덕적** | 회색지대 명확 | 흑백 단순 |
| **정보** | 불완전한 정보 완전한 정보 |
| **되돌림** | 되돌릴 수 없음 | 쉽게 재시도 |

**예시:**
```
[상황] 마을에 역병이 돌고 있다. 한 집에 약이 1개 남았다.

선택 A: 아이에게 준다
→ 아이 생존, 마을 사람 10명 사망
→ 10년 후: 아이가 영웅이 됨

선택 B: 마을 사람들을 살린다
→ 아이 사망, 마을 구함
→ 10년 후: 마을은 번창, 아이의 어머니가 원망

선택 C: 약을 연구한다
→ 둘 다 위험, 시간 쟁탈
→ 결과 불확실
```

### 3. 감정적 트리거

**플레이어 감정 조작 기법:**

| 기법 | 설명 | 예시 |
|------|------|------|
| **교육** | 기대 형성 후 깨뜨림 | 친절한 NPC가 배신 |
| **희생** | 아깝게 만든 후 잃게 함 | 함께 성장한 동료 사망 |
| **선택** | 책임감 부여 | 플레이어 선택의 결과 |
| **공감** | 자신의 경험 연결 | 가족, 사랑, 상실 |
| **정의** | 불의한 상황 해결 | 약자 구하기 |

## Next.js로 스토리 게임 구현

### 감정 분석 시스템

```typescript
// lib/emotion-tracker.ts
interface EmotionalState {
  tension: number;      // 0-100: 긴장감
  empathy: number;      // 0-100: 캐릭터 공감도
  curiosity: number;   // 0-100: 다음 장면 기대감
  agency: number;       // 0-100: 선택의 영향력 인식
}

// 감정 변화 추적
export function trackEmotionalJourney(
  choices: Choice[],
  emotionalLog: EmotionalState[]
): EmotionalState {
  const current = emotionalLog[emotionalLog.length - 1];
  
  // 선택지 특성에 따른 감정 변화
  const impact = calculateEmotionalImpact(choices);
  
  return {
    tension: clamp(current.tension + impact.tensionDelta, 0, 100),
    empathy: clamp(current.empathy + impact.empathyDelta, 0, 100),
    curiosity: clamp(current.curiosity + impact.curiosityDelta, 0, 100),
    agency: clamp(current.agency + impact.agencyDelta, 0, 100),
  };
}

// 플레이어 유형 분석
export function analyzePlayerType(history: Choice[]): PlayerArchetype {
  const altruism = countAltruisticChoices(history);
  const pragmatism = countPragmaticChoices(history);
  const curiosity = countCuriosityChoices(history);
  
  if (altruism > pragmatism && altruism > curiosity) {
    return 'ALTRUIST'; // 이타주의자
  } else if (pragmatism > altruism && pragmatism > curiosity) {
    return 'PRAGMATIST'; // 실용주의자
  } else {
    return 'EXPLORER'; // 탐험가
  }
}
```

### 동적 스토리 생성

```typescript
// lib/dynamic-story.ts
interface StoryContext {
  playerType: PlayerArchetype;
  emotionalState: EmotionalState;
  previousChoices: Choice[];
  playTime: number;
}

// 플레이어에 맞춘 콘텐츠 제공
export function generatePersonalizedContent(
  context: StoryContext,
  baseBranch: Branch
): Branch {
  const personalized = { ...baseBranch };
  
  // 감정 상태에 따른 분위기 조정
  if (context.emotionalState.tension > 80) {
    // 너무 긴장됐으면 잠시 휴식 장면
    personalized.content = addBreathingRoom(personalized.content);
  }
  
  // 플레이어 유형에 따른 선택지 우선순위
  personalized.choices = reorderChoicesByPlayerType(
    personalized.choices,
    context.playerType
  );
  
  return personalized;
}
```

### 저장/로드 시스템

```typescript
// lib/save-system.ts
interface SaveData {
  id: string;
  name: string;
  timestamp: Date;
  gameState: GameState;
  emotionalLog: EmotionalState[];
  playTime: number;
  screenshot?: string; // 썸네일
}

export async function createSave(
  userId: string,
  name: string,
  gameState: GameState
): Promise<SaveData> {
  const save: SaveData = {
    id: generateUUID(),
    name,
    timestamp: new Date(),
    gameState,
    emotionalLog: getEmotionalLog(),
    playTime: getTotalPlayTime(),
    screenshot: await generateScreenshot(),
  };
  
  await db.saves.create({ userId, ...save });
  return save;
}

export async function loadSave(
  userId: string,
  saveId: string
): Promise<GameState> {
  const save = await db.saves.findOne({ userId, id: saveId });
  
  // 감정 상태 복원
  restoreEmotionalState(save.emotionalLog);
  
  return save.gameState;
}
```

## 엔딩 설계

### 엔딩 타입 분류

```
[엔딩 스펙트럼]

비극적 ←——————————→ 희극적
Bad End         Normal End         Good End
(영웅 사망)     (대부분 생존)      (완벽한 해결)
    ↓                ↓                 ↓
도전 과제       표준 플레이      완전 탐구
```

### 엔딩 트리거 조건

```typescript
// lib/ending-conditions.ts
interface EndingCondition {
  id: string;
  name: string;
  description: string;
  check: (state: GameState) => boolean;
}

const endings: EndingCondition[] = [
  {
    id: 'sacrifice_ending',
    name: '희생의 엔딩',
    description: '자신을 희생해 다른 사람을 구함',
    check: (state) => 
      state.flags['sacrificed_self'] === true &&
      state.stats.health <= 0
  },
  {
    id: 'survivor_ending',
    name: '생존자 엔딩',
    description: '모두와 함께 살아남음',
    check: (state) =>
      state.flags['all_survived'] === true &&
      state.stats.health > 50
  },
  {
    id: 'lone_wolf_ending',
    name: '외톨이 엔딩',
    description: '혼자서만 살아남음',
    check: (state) =>
      state.flags['companions_died'] === true &&
      state.stats.health > 0
  },
  {
    id: 'true_ending',
    name: '진 엔딩',
    description: '모든 비밀을 밝히고 완전한 해결',
    check: (state) =>
      state.flags['found_all_secrets'] === true &&
      state.flags['solved_mystery'] === true &&
      state.flags['all_survived'] === true
  }
];
```

## 성공 사례 분석

### 1. Undertale (Toby Fox, 1인 개발)

**성공 요인:**
- ✅ 혁신적인 메타-게임플레이 (게임이 플레이어를 직접 주시)
- ✅ 캐릭터 메모리 (선택이 다음 플레이에 영향)
- ✅ 복수 엔딩 (22개)
- ✅ 감정적 교류 (Sans, Papyrus 캐릭터)

**개발 기간:** 2.7년
**예산:** $0 (무료 에셋 사용)
**수익:** $50M+

### 2. Disco Elysium (ZA/UM, 20인)

**성공 요인:**
- ✅ 문학적 퀄리티의 서사
- ✅ 깊은 캐릭터 빌딩
- ✅ 독특한 스킬 시스템 (내면적 목소리)
- ✅ 정치적, 철학적 주제

**개발 기간:** 4년
**수익:** $10M+

스토리 기반 게임은 **기술보다 서사**가 핵심입니다. 캐릭터, 플롯, 세계관의 균형을 맞추고, 플레이어의 감정을 고려한 설계가 필요합니다.

1. ✅ 캐릭터 프로필 3개 작성

3. ✅ 첫 분기점 5개 작성
